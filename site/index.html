Pick how you want to get it

Both options give you the same extension. Option 1 is the quick route. Option 2 gives you a repo that tests itself, builds the zips, and publishes this website for you.

Download, extract, load


Download uwpo-chromium.zip

  1. Extract the zip into a folder you will keep. The browser reads the extension from that folder, so do not delete it afterwards.
  2. Open chrome://extensions (Edge: edge://extensions) and switch on Developer mode.
  3. Click Load unpacked and choose the extracted folder, the one that directly contains manifest.json.
  4. Pin the extension from the puzzle-piece menu, open any website and click the icon. The popup shows the status for that site.
  1. Extract the zip into a folder you will keep.
  2. Open about:debugging#/runtime/this-firefox.
  3. Click Load Temporary Add-on and choose the manifest.json inside the extracted folder.
  4. Open a website and click the toolbar icon. Temporary add-ons are removed when Firefox closes, so repeat step 3 next session. If nothing happens on pages, check the extension permissions in about:addons.

Chrome on Android does not run extensions, so use Firefox for Android (115 or newer). Firefox on Android only installs signed add-ons, so the plain zip will not install there.

  1. Get a signed file. Follow Option 2 and add the two Mozilla API secrets. Your first tagged release then attaches uwpo-firefox-signed.xpi. Details are in Phones and tablets.
  2. On the phone, open your repo's Releases page in Firefox and download that .xpi.
  3. In Firefox open Settings, tap the Firefox logo five times to enable the debug menu, then choose Install add-on from file. That entry has appeared in some Firefox versions and not others.

Update your GitHub repo in five steps

Your repo already has an earlier version of the project. The download below is a folder with that history plus one new commit on top, so a normal push updates it and nothing is lost.

    cd Optimser-extantion
git remote set-url origin https://github.com/anitikrish-ai/Optimser-extantion.git

  3. Turn on Pages. In the repo open Settings, Pages, and set Source to GitHub Actions.
  4. Wait for the green check. Every push runs typecheck, tests and the build. Then the site is live at https://anitikrish-ai.github.io/Optimser-extantion/, and its download buttons serve zips built from your source.

Getting it onto a phone

Firefox for Android refuses unsigned add-ons. Create free API keys at addons.mozilla.org (Developer Hub, Manage API keys), then add them to your GitHub repo as secrets named AMO_JWT_ISSUER and AMO_JWT_SECRET. The next tagged release signs the build as an unlisted add-on and attaches uwpo-firefox-signed.xpi.

For developer testing, enable USB debugging on the phone and run this on your computer:

npm run build
npm run android

What it actually does

Each row names a mechanism and the limit of what it can do. Nothing here is a promise about any particular page.

AreaMechanismLimit
NetworkThe browser blocks requests to bundled lists of session-replay, analytics and ad hosts, plus your own host-based rules.The extension never sees request contents. Blocked requests never download, so no data-saved number is shown.
ImagesAdds lazy loading to images below the first screen that have not started loading, plus async decoding.Cannot cancel a request already started.
VideosPauses videos that start before any interaction, and muted videos that scroll away or sit in a background tab. Resumes only what it paused.Audible video and Picture-in-Picture are never paused.
RenderingPauses endless CSS animations while offscreen. At Extreme only, removes backdrop-filter.Removing blur can hurt legibility of translucent overlays.
DOMApplies content-visibility: auto to large sections far below the fold.Skips forms, navigation, dialogs, frames and fixed elements. Can clip overflow on some sites.
CPU and memoryNo switch of its own. Effects come from the items above.It cannot throttle page timers or free page memory, and does not pretend to.

Earlier versions also tried timer throttling, scroll throttling, canvas pausing and battery-based decisions. They were removed because a content script cannot do them reliably.

Modes and safety

Pick Adaptive, Balanced, Performance or Extreme. Adaptive only chooses an intensity. It never enables a module you turned off and never lowers the level mid-page.

Which setting wins

  1. Global settings
  2. Per-site settings, longest matching hostname first
  3. The adaptive engine
  4. Safety, applied last, always wins

Safety switches everything off for

Sign-in, payment, CAPTCHA and local development hosts. Non-http(s) pages. Your skip list. Sign-in or checkout paths. Tabs you paused. Any page where a password field, card field, CAPTCHA frame or payment frame appears. If one appears mid-page, all changes are rolled back and blocking is bypassed for that tab.

If a site breaks

Try these in order. Each one undoes more.

  1. Pause on this tab in the popup. Removes all page changes, stops blocking for that tab and reloads it. Unsaved input is lost.
  2. Skip this site. Never optimizes the site or blocks requests it starts.
  3. Master switch. Turns everything off in every tab and disables all bundled rulesets.
  4. Reset everything in the dashboard.

Every page change is undone by a single restore step. The tests compare the page HTML before and after to check this.

Numbers you can trust

Every number in the extension carries one of three labels.

MeasuredEstimatedUnavailable

Measured comes from a browser API. Estimated must state its method, and the extension ships no estimates today. Unavailable means the browser does not expose it, for example heap size outside Chromium.

Before and after reloads the page twice, once without and once with the optimizer, and shows only metrics measured in both runs. It uses single runs, so treat small differences as noise. The 60 to 70 percent figure in the project README is a design target for avoidable overhead on suitable heavy pages, not a measured result.

Privacy and permissions

No network code of its own, no analytics, no backend, no remote configuration. State lives in session storage and is cleared when the browser closes. Per open tab it keeps only the hostname, never the URL or path. A test fails the build if the source contains fetch, XMLHttpRequest, WebSocket, web storage or cookie access.

PermissionWhy
storageSession-only settings and per-tab data
declarativeNetRequestThe browser blocks listed requests without the extension seeing them
activeTabLets the popup read the blocked-request count for its tab (Chromium)
Content script on http and httpsApplies page-level changes. Browsers show this as access to all websites, and it is the one broad access needed

It does not ask for tabs, webRequest, cookies, history or scripting. Because settings reset each session, use Export settings and Import settings in the dashboard to keep a copy.

Architecture in one picture

popup / dashboard  --SET_CONFIG, TAB_PAUSE-->  background
content script    --GET_PLAN, REPORT_SAMPLE-->  background
background        --PLAN_CHANGED, RESTORE_NOW--> content script
background        --declarativeNetRequest-->    browser network stack

Four plain bundles are built from src/: background, content, popup and options. The network priority order, highest first, is user allow, essential allow for sign-in and payment providers, custom block, bundled block. So no block rule can break a login or a payment. In the page, one shared observer does work in slices of at most 8 ms and stops after 1000 ms of total own work. These are design limits, not profiled results. Full detail is in docs/ARCHITECTURE.md.

Questions

Does it send my browsing anywhere?

No. The extension contains no code that makes network requests, and the test suite audits for that.

Why do my settings disappear when I close the browser?

On purpose. Saving a skip list and per-site settings would create a local record of the sites you visited. Export and import are there if you want to keep a copy.

Why Developer mode and Load unpacked?

This build is not in a browser store. Loading it from a folder is how browsers run unpacked extensions.

A video I wanted to autoplay is paused.

The autoplay guard pauses any video that starts before you interact, including muted hero loops. Click it to start it, or use Skip this site.

Can I add my own block rules?

Yes, in the dashboard. Rules block by hostname, optionally with a path. They cannot use regular expressions, and they cannot target sign-in or payment providers.
